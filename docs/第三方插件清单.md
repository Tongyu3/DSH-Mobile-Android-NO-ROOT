> 面向：发布/分发时的免责声明、Release 说明、README。
> 数据来源：**装机版本 `@deepseek-ai/dsh@0.2.0-rc.2` 的 npm 依赖元数据** +

> 最后核对：2026-09-30。

## 一、结论（先看这三句）

1. **随 APK 打包的第三方插件：0 个。**
   APK 的 `assets/` 里只有一个插件包 `dsh-phone-1.0.2.tgz`，是**本项目自研**的代码
   （按你的口径不算第三方）。
2. **首次运行时自动装进容器的插件，全部来自 DeepSeek 官方**（npm `@deepseek-ai/*`）：
   应用会执行 `npm install -g @deepseek-ai/dsh`，其依赖树含 **223 个 `@deepseek-ai/*` 包**，
   全部是 DeepSeek 的官方包。
3. **第三方社区插件只能由用户自己装**（App 的「插件市场」搜的是 npm 上带 `dsh-plugin`
   标签的包）。本项目**不预置、不推荐、不担保**任何一个；装与不装、装哪个，都由用户决定。

> 所以免责声明的落点不是"我打包了谁的插件"，而是：
> **本应用运行的是 DeepSeek 官方 DSH 及其插件；用户自行安装的第三方插件，其行为与责任归该插件作者。**

## 二、真机实测：界面上看到的就是这些

手机上 DSH 设置 →「插件」页面（2026-09-30 实拍）：

| 分区 | 数量 | 内容 |
|---|---|---|
| **官方** | **8** | 智能体团队（实验性）· 自动授权审查（实验性）· 自动化任务（实验性）· 语音输入（实验性）· 终端 · Agent 循环 · 子智能体 · 网页搜索 |

## 六、怎么自己复核（三条命令）

```powershell
# 1) APK 里到底打包了哪些插件（只应看到一个自研的 tgz）
dir DshMobile\app\src\main\assets\*.tgz

# 2) 装机版本的官方插件包到底有多少（示例：0.2.0-rc.2）
npm view @deepseek-ai/dsh@0.2.0-rc.2 dependencies
npm view @deepseek-ai/dsh-base@0.2.0-rc.2 dependencies

# 3) 容器里实际装了什么（在手机的 DSH 终端里跑）
npm ls -g --depth=1
```

手机上最直观：DSH 设置 →「插件」→ 顶部写「官方 8 / 已安装 1」，逐条点开即可看到来源与说明。
